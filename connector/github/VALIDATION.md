## 完成后的静态复核

逐文件复核 10 个应用模块、5 个测试/验收模块、配置、锁文件、构建白名单、官方契约说明
和交付产物；重点检查权限、资源边界、响应校验、截止时间、重试与副作用。

复核发现并完成修正/验证：

1. **SDK 的 3xx 限制。** b9 在暴露 Location 前拒绝重定向，不能直接使用消费回调处理。
   仅对该 SDK 错误增加公开资源管理下的只读适配；只重复原 GET，不重发写入或其他失败。
   限制同源、资源路径类型、跳转次数、响应长度/EOF 和原始截止时间。
2. **畸形列表可能被当作成功。** 非文件列表要求有效数字 id；安装发现保留并验证
   total_count，缺失值不推算。
3. **分页跳过结果。** next 页必须为当前页加一，重复参数、逆序/跳页、大小变化和
   不相关资源链接拒绝；应用只取页号，不派发服务返回的任意 URL。
4. **PR 覆盖范围误判。** 校验 PR 编号类型，拒绝重复文件；核对前后 SHA/文件数，
   即使文件列表完整也不将 patch 片段声称为完整 diff。
5. **写入与限流边界。** 预检失败时尚未派发写入，明确拒绝；写后失败保留 uncertain。
   冷却和写间隔在原始截止时间内执行；冷却不持有任何凭据。
6. **GitHub 特有授权语义。** 空 scope 不制造权限快照；客户端明确拒绝只在可信的
   成功/确定错误状态分类，503/429 不触发旧刷新凭据保留路径。

最终修正后重新运行源码测试、独立构建、consumer 测试和正式 CLI 验收。
复核范围内无保留的阻断问题。

重定向路径自行限制每响应 1 MiB，不读取 SDK 私有预算状态；低 HTTP 字节预算的宿主需
补验该路径。必要资源清理可能超过业务截止时间，迟到业务结果不能成功。
限流冷却在进程内按连接保存，重启和其他安装/客户端的流量不在此状态中。
写前读取和 PR 前后核对都不是服务端事务；分页过程中变化、并发写入、标签删除等仍可能
改变最终行为，应用不通过自动重试、权限回退或假完整结果隐藏这些限制。
