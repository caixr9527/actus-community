- Token：无效凭据、部分权限裁剪、过期后并发刷新串行化、轮换与重启复用、

  超大数字、字段定义逐次读取、分页、重复/不完整定义及循环游标。
- 失败：业务错误、权限不足、资源不存在、限流、重复 JSON key、非有限数字、

## 完成后的静态复核

逐文件复核全部 8 个应用模块、配置与构建清单、测试辅助代码、文档和最终产物。
重点检查授权边界、资源 token、参数与响应验证、错误分类、截止时间、刷新轮换、
日志内容、写入前后边界及安装独立性。

本轮检查发现并修正：

1. **刷新权限快照可能过时。** 每次业务派发再检查当前凭据 scope，阻止刷新裁剪后沿用旧能力。
2. **自定义凭据投影可能携带刷新材料。** 显式投影为 `OAuthAccessCredential`，业务上下文只获得访问凭据与 scope。
3. **写前预检错误与写后未知结果需分开。** 字段 schema 读取/解析失败尚未派发记录写入，
   使用 `OperationRejected`；写入发出后的错误保持 `uncertain`。
4. **超大整数转浮点可溢出。** 数字校验先检查范围，再判断有限性，避免写前溢出变成未知结果。
5. **固定 SDK 错误会丢失细分类别。** 将应用的固定诊断码写入宿主日志，不记录厂商正文；
   SDK 对外仍使用标准的失败/未知状态。
6. **独立启动需要显式 HTTP 预算。** 验收辅助程序补齐 `http_options`，README 明确宿主要求。

修正后重新执行源码测试、重建最终包、独立安装、逐文件一致性校验及 TLS CLI 验收。
复核范围内没有保留未处理的阻断问题。
